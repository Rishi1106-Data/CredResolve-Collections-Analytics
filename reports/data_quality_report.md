# Data quality report

Flow: **Raw → Rejected/Corrected → Golden** (full counts in `reports/cleaning_summary.md`; every removed row is in `rejects/`).

| # | Issue | Detection | Treatment | Business impact |
|---|---|---|---|---|
| 1 | Duplicate payments: 500 repeated `payment_id` (486 exact copies, 14 with a missing reference in one copy) | `duplicated()` on all columns; repeated IDs with different content | Exact copies dropped; conflicts merged (reference filled, first-ingested row kept) | Duplicates inflate SUCCESS recovery by **1.97%** (₹134.15 Cr raw vs ₹131.56 Cr clean). Retry/ingestion duplicates do not create the 11%: raw SUCCESS Feb→Mar is +10.99% vs +11.03% clean |
| 2 | `payment_reference` is NOT unique (20,821 distinct values across 25,500 raw rows; 382 null; the same reference appears on different accounts and amounts) | reference counts across different accounts/amounts | Not used as a dedupe key | Using it would wrongly delete real payments |
| 3 | Non-SUCCESS payments: FAILED 14.8%, PENDING 10.1%, REVERSED 5.0% of rupees | `payment_status` | Only SUCCESS counted as recovery | A report counting all statuses is **45.7% higher** than valid recovery and shows Mar/Feb +12.2% |
| 4 | Calls: 1,350 repeated `call_id` (1,271 exact copies; 79 conflicts: 68 missing agent, 11 timestamps shifted 1–5 days) | as above | Exact dropped; agent filled; first-ingested row kept for shifted timestamps (alternate logged) | 1.4% of raw call rows were duplicates |
| 5 | Timezones: calls labelled UTC / Asia/Kolkata / Asia/Dubai; payments and PTPs unlabelled | `timezone` column | Calls: `event_at_utc_assumed` added (assumes local time in label); others left unconverted and flagged | Under the assumption 13.2% of calls change date, 66.7% change hour, 397 change month → hour/day analysis provisional |
| 6 | Borrower identity: 30,600 rows, 11,015 IDs; 8,518 IDs have conflicting attributes; 15,063 rows `updated_at < created_at`; 2,458 account `borrower_id`s absent from borrowers; 455 accounts with null `borrower_id` | key uniqueness, cross-table joins | **No record chosen as truth**: all rows kept (600 exact copies dropped), labelled UNRESOLVED; nothing imputed | Geography and unique-borrower metrics unreliable → not reported |
| 7 | Agent identity: 1,000 `agent_id`s over 30,000 rows; ~29 employee codes per agent_id; ~26 agent_ids per employee_code; 1,759 calls without agent | key uniqueness, crosswalk check | All rows kept, labelled; `agent_id` used only as a grouping key | Agent tenure/productivity not reported |
| 8 | Disposition codes: `PTP` and `PROMISE_TO_PAY` both exist; versions legacy/v1/v2 are spread evenly over months; 79.8% of dispositions are on unanswered calls | code counts by version and month | Treated as aliases; used only as a labelled RPC proxy | No evidence of a mapping change moving a metric; disposition data unreliable |
| 9 | PTP status stale: 4,128 matured promises still OPEN; KEPT barely differs from BROKEN in payments; accounts hold several promises so one payment could be counted twice | joined to SUCCESS payments; window-overlap check | Un-matured excluded (1,242); kept rate reported as a range (one payment → one promise 3.67% to overlap-allowed 3.71%) | Recorded kept rate 49.76% (of KEPT+BROKEN) is not supported by payments |
| 10 | Account snapshot inconsistencies: 25% WRITEOFF/25% PAID/25% CLOSED yet 75% of recovery comes from them; 1,862 SUCCESS payments > outstanding; 1,793 accounts recovered more than snapshot balance; status history agrees with accounts.status for 14.2% of accounts | joins, `src/denominators.py` | Flagged, kept | Eligible balance cannot be established: recovery ÷ outstanding is an index, not a collection rate |
| 11 | Window: payments end 8 Aug (partial month), calls span 29 Dec–12 Aug (5 rows outside window) | min/max dates | Aug excluded from MoM; 5 calls flagged | "12 months" in the brief is actually ≈7.2 months |
| 12 | Denominator check: accounts opened 2024-01-01…2025-11-30 (all before window); terminal-status share steady ≈43% each month | opened_at range; status history as of each month start | none possible | No sign of accounts leaving the base or new acquisition; eligible denominator still not establishable |
| 13 | Late-arriving / overwritten: 11 call conflicts shifted 1–5 days; no payment before account opening | conflict diff | first-ingested kept | Negligible |
